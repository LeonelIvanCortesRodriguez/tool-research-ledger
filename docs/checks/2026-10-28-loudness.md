# Check: story video loudness

Date: 2026-10-28. Tool: FFmpeg's EBU R128 `loudnorm` filter, measuring only (`node video/loudness.mjs <file>`).

## Expected (written before the run)

Input: `docs/video/story-en.mp4` and `docs/video/story-es.mp4`. Each carries the narration track normalized by `video/assemble.mjs` with two-pass `loudnorm` (target -16 LUFS, true peak -1.5 dBTP), then encoded to AAC 160 kb/s by `video/finish.mjs`. HyperFrames renders the frames only, so it cannot change the level.

- Both files: integrated loudness between -17.0 and -15.0 LUFS (target -16 within 1 LU), expected about -16.2, since the AAC encode moves the level by a few tenths at most.
- True peak at or below -1.0 dBTP.
- The command prints `PASS` for both files and exits 0.

## Actual

`node video/loudness.mjs docs/video/story-en.mp4 docs/video/story-es.mp4`, exit 0:

```
PASS story-en.mp4 -16.2 LUFS (target -16 within 1 LU), true peak -1.44 dBTP
PASS story-es.mp4 -16.7 LUFS (target -16 within 1 LU), true peak -1.46 dBTP
```

Both pass. English matches the estimate. Spanish is 0.5 LU quieter than the -16.2 estimate but inside the range: the normalized WAV already measured -16.7 before the encode (`video/assemble.mjs` printed `voice -16.7 LUFS`), so the gap comes from the linear loudnorm pass stopping at the -1.5 dBTP peak limit, not from the encode.
